# Résumé Review Checklist

Run this end to end. For each miss, report the **file:line**, the **rule**, and a
**concrete fix**. Source: r/EngineeringResumes wiki.

## General formatting

- [ ] **Single-column layout.** No multi-column résumé bodies.
- [ ] **No icons, images, or graphics.** Text only.
- [ ] **Bullet points, not paragraphs**, for every role and project.
- [ ] **No manual indentation** of sections/bullets — the bullet glyph already indents.
- [ ] **Modern, readable font:** Calibri, Bitstream Charter, Arial, Lato, or Helvetica.
- [ ] **Black font, not thin, ≥10.5pt.** Must print legibly in grayscale; enough contrast
      against white.
- [ ] **Don't justify text** — it creates uneven word spacing. Left-align.
- [ ] **Enough white space.** No cramming. Margins ≥0.4in, line spacing ≥1.07.
- [ ] **Clear section separation.** Sections are visually distinct; consistent white space
      between sections, subsections, and each job/project.
- [ ] **Sparing emphasis.** Avoid excessive italics, bold, and ALL CAPS. If used, use each
      independently (don't bold + italic + caps the same text). Don't bold keywords inside
      bullets — it's distracting.
- [ ] **Length: 1 page per decade.** Default to 1 page; 2 pages only for senior/staff with
      enough relevant content. Never pad to fill a second page.

## Contact information

- [ ] **One email address**, from a modern provider (Gmail/Outlook), not AOL/Hotmail/Yahoo.
- [ ] **Plain text links**, not masked markdown. Write `name@gmail.com`,
      `github.com/username`, `myportfolio.com` directly.
- [ ] **No labels** like "Email:", "Phone:", "GitHub:", "Portfolio:".
- [ ] **No `https://www.`** prefix on URLs.
- [ ] **No underline/italic/color** on contact links.
- [ ] **No physical address / ZIP.**
- [ ] **No city/state** unless the specific job is in that city (non-local location → bias).
- [ ] **LinkedIn is optional/unnecessary** — recruiters can search the name.
- [ ] **Phone optional.** If listed: no "Cell:/Mobile:" prefix; omit `+1` in US/Canada.
- [ ] **No empty GitHub link.** Only link GitHub/portfolio if current and substantive.
- [ ] **Security clearance** (if any) can go by the name, e.g. "Top Secret / SCI eligible."
- [ ] **Work-authorization/citizenship** near the name only if needed to signal no
      sponsorship required, e.g. "US Citizen", "Canadian Citizen".

## Dates

- [ ] **`Present`**, not "Current", "Now", or "Ongoing", for active roles.
- [ ] **Consistent granularity.** If using months, use months everywhere; no seasons or
      semesters ("March 2022", never "Winter 2022").
- [ ] **No specific days** ("January 1, 2023").
- [ ] **Full years**, never abbreviated ("'23").
- [ ] **No numeric months** ("9/2013").
- [ ] **Proper month abbreviations** if abbreviating: Jan, Feb, Mar, Apr, May, June, July,
      Aug, Sept, Oct, Nov, Dec — and **no periods** ("Sept", not "Sept.").
- [ ] **En dashes for ranges** (`–`), not hyphens or "to".
- [ ] **Spaces around the en dash:** `Mar 2012 – Mar 2022`, not `Mar 2012–Mar 2022`.
- [ ] **Dates right-aligned** to the right margin.
- [ ] **Bullets never extend further right than the dates.**

## Section order

- Working full-time (this user): **Experience → Skills → Education** (or Skills → Experience
  → Education).
- Student/new grad: Education → Experience → Skills (or Education → Experience → Projects →
  Skills).
- No technical work experience: Education → Projects → Experience → Skills.
- No experience at all: Education → Projects → Volunteer/Extracurriculars → Skills.
- [ ] **No summary/profile** unless senior/staff+, career changer, or addressing an
      employment gap. (This user qualifies — a ≤2-sentence summary is allowed.)
- [ ] **No references section.**

## Effectiveness

- [ ] **Relevant, technical detail** that distinguishes the candidate — not generic duties.
- [ ] **Context + keywords** so the hiring team understands the work and it parses in ATS.
- [ ] **No filler** that doesn't strengthen candidacy.
- [ ] **Most important details top-left** — increases odds of being read.
- [ ] **Tailored to the target role** / job description where possible.

## Grammar, punctuation, spelling

- [ ] **Spell out obscure abbreviations on first use**, lowercase the expansion:
      "scanning tunneling microscope (STM)", not "Scanning Tunneling Microscope (STM)".
- [ ] **Capitalize only proper nouns.** Run a grammar check, not just spell check.
- [ ] **No typos.** They read as poor attention to detail and can sink the résumé. Use
      Grammarly / Hemingway / LanguageTool / Quillbot, and have a human proofread.

## Bias

- [ ] **No personal details** that invite bias: age, gender, children, nationality,
      ethnicity, marital status, religion, political views, photo.
